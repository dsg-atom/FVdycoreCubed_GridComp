## 11. Implementation Reality — Current Truth by Work Package

This section reconciles two sources: `docs/agent_handoff/implementation_reality_audit.md`
(dated 2026-08-21, an independent 7-way code audit that read actual kernel
definitions rather than filenames/declarations) and `docs/agent_handoff/milestone_3a2_wp_d_activation.md`
(also dated 2026-08-21, same day, and confirmed by `git log` to correspond to
current HEAD commit `8f94c4f`). **The milestone doc supersedes the audit's
findings for the four stages it activated** — this was checked directly
against current source (`fv3_gpu_production_dispatch.cu`, `fv3_gpu_runtime.cpp`),
not taken on the audit's or the handoff's word alone.

**The superseded claim, explicitly flagged:** an earlier handoff
(`integration.md:469-477`) stated *"Production GEOS first-run numerical path:
COMPLETE. All 54 required numerical stages ... are now implemented ... No
PARTIAL or UNIMPLEMENTED stages remain."* The audit shows this table's own
"54" doesn't even match its own itemized row count (49), and — more
importantly — that every one of those 49 rows carried `CUDA=NOT RUN, GPU=NOT
RUN` in the same table whose prose claimed completeness. "COMPLETE" meant
*host C++ reference passes a CPU unit test*, not GPU execution. **This claim
should not be repeated without this correction.**

**What has changed since the audit (verified in source, not from commit
messages alone):** `fv3_gpu_dyn_core_step` (`cuda/dyn_core/runtime/fv3_gpu_runtime.cpp:160`)
is **no longer a stub**. It now builds a real `NumericalDispatch` via
`fv3_build_production_dispatch()` (`fv3_gpu_production_dispatch.cu`) and
invokes a 4-stage loop (`cgrid_pressure`, `vertical_solver`, `nh_pressure`,
`post_loop_heating`), skipping unwired null slots rather than failing
unconditionally as it did at audit time.

```bash
# Repository root

# Branch archaeology
git branch -a
git rev-list --count ac43844..<ref>          # per-branch commit counts
git show <sha> | git patch-id                # content-identity check across re-commits
git log --format=%H ac43844..<ref> | sort -u | wc -l   # SHA dedup across all refs

# LOC — baseline-to-endpoint diffs (never per-commit summation)
git diff --numstat ac43844..8f94c4f     > total.numstat
git diff --numstat ac43844..a395538     > adapt.numstat
git diff --numstat a395538..8f94c4f     > discover.numstat
git diff --shortstat <BASE>..<END>      # cross-check totals against categorized sums

# Each *.numstat file categorized by extension (CUDA/.cu,.cuh; CPP/.c,.cc,.cpp,.cxx;
# HEADER/.h,.hpp; FORTRAN/.F90,.f90; BUILD/CMakeLists.txt,.cmake; DOC/.md,.rst;
# JSON/.json) with an orthogonal istest flag (path matches /test/i), via a small
# awk script; categorized sums were cross-checked against `git diff --shortstat`
# for each window and matched exactly (e.g. TOTAL: 9,115 impl + 2,693 test + 8,748
# doc + 25 json = 20,581 insertions, matching shortstat exactly).

# Current-repository inventory (independent of history)
find cuda -name '*.cu'; find cuda -name '*.cuh'
grep -ro "__global__" cuda/dyn_core --include=*.cu --include=*.cuh | wc -l
grep -ro "__device__" cuda/dyn_core --include=*.cu --include=*.cuh --include=*.hpp --include=*.cpp | wc -l
grep -rc "__global__\|__device__" cuda/dyn_core/dgrid/*    # WP-B zero-kernel confirmation
find cuda -iname "*test*" -type f | wc -l
find . -name "*.md" -not -path "./build_cuda*" | wc -l

# Fortran-modification scope check
git diff --stat ac43844..8f94c4f -- geos-gtfv3     # empty
git diff ac43844..8f94c4f -- FV_StateMod.F90        # read to confirm no algorithm lines touched
```

**Why `git diff PRE_CUDA_BASELINE..CURRENT_HEAD` is authoritative:** commit-
by-commit summation double-counts any file edited more than once (every WP's
"foundation" → "contract v2" → "contract v3" → "complete" commit sequence
touches the same files repeatedly) and cannot account for the manual-recommit
integration pattern documented in Section 5/15, where the same logical change
appears under multiple, non-identical SHAs across branches. A single
baseline-to-endpoint tree diff is immune to both problems: it reflects only
the net difference between two actual tree states, which is what "how much
did the codebase change" means. All headline LOC numbers in this report
originate from exactly this method, verified by shortstat cross-checks.
